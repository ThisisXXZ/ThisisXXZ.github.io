对称与非对称密钥

Symmetric or Asymmetric Key(s).

The concept of symmetry and asymmetry refers to the keys distribution in 2 parties (sender and receiver). If the information is encoded and decoded with the same key kkk, we say the scheme is symmetric. Otherwise, it is asymmetric.

Private Key Encryption and MAC

Private key encryption scheme and message authentication code (MAC) are symmetric primitives. In fact, private key encryption scheme is also called symmetric encryption.

Private key encryption: Alice encrypts the message mmm by running Enck(m)→cEnc_k(m)\to cEnck​(m)→c. Bob decrypts the ciphertext ccc by running Deck(c)→mDec_k(c)\to mDeck​(c)→m.

Message authentication code (MAC): Alice authenticates mmm by running Mack(m)→tMac_k(m)\to tMack​(m)→t. Bob verifies the tag ttt by checking Vrfyk(m,t)Vrfy_k(m,t)Vrfyk​(m,t) equals to 111 or not.

Message Authentication Code (MAC) provides integrity, which ensures that the information is not tampered during transmission.

Alice applies the MAC algorithm to mmm and produces an unforgeable tag t:=Mack(m)t:=Mac_k(m)t:=Mack​(m). Alice sends the tag ttt along with the message mmm: Bob then verifies the tag to check whether the message mmm is tampered or not.

Public Key Encryption and Digital Signature

Public key encryption scheme and digital signature are asymmetric primitives. Public key encryption scheme is also called asymmetric encryption.

In asymmetric primitives, the key-generation algorithm Gen(1n)Gen(1^n)Gen(1n) will produce a pair of keys ⟨pk,sk⟩\langle pk, sk \rangle⟨pk,sk⟩. The public key pkpkpk is publicly distributed, while private key sksksk is only held by one party.

Public key encryption: Alice encrypts the message mmm with public key pkpkpk by running Encpk(m)→cEnc_{pk}(m)\to cEncpk​(m)→c. Bob decrypts the ciphertext ccc with private key by running Decsk(c)→mDec_{sk}(c)\to mDecsk​(c)→m.

Digital signature: Alice signs mmm with private key by running Signsk(m)→σSign_{sk}(m)\to \sigmaSignsk​(m)→σ. Bob verifies the signature σ\sigmaσ by checking Vrfypk(m,σ)Vrfy_{pk}(m, \sigma)Vrfypk​(m,σ) equals to 111 or not.

Note that in public key encryption, receriver Bob holds the private key; while in digital signature, sender Alice holds the private key.

MAC Versus Digital Signature

MAC and digital signature both provide integrity. However, the asymmetry of digital signature guarentees more than that.

  • Public Verifiability

    A third party not directly participating in the protocol should also be able to verify the generated values. It is based on the publicity of pkpkpk. MAC cannot achieve this since kkk must be kept secret for the defence of a malicious third party.

  • Transferability

  • Non-repudiation

    Once the signer signs a message mmm, he can NOT deny having done so afterwards. It is based on the secrecy of sksksk: sksksk is only known by signer and is paired up with pkpkpk. Anyone with pkpkpk could convince that signer holds sksksk with zero-knowledge of sksksk.
