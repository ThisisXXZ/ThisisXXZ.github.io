Merge Sort

Basic idea of mergesort is divide-and-conquer paradigm.

  • Divide array into two halves.
  • Recursively sort each half.
  • Merge two sorted halves using two pointers.

In empirical analysis of merge sort, # compares is denoted by C(N)C(N)C(N), # array accesses is denoted by A(N)A(N)A(N). It is proven that C(N)≤Nlg⁡NC(N)\leq N\lg NC(N)≤NlgN and A(N)≤6Nlg⁡NA(N)\leq 6N\lg NA(N)≤6NlgN for any array of size NNN.

Proposition. if D(N)=2D(N/2)+ND(N)=2D(N/2)+ND(N)=2D(N/2)+N for N>1N>1N>1, with D(1)=0D(1)=0D(1)=0, then D(N)=Nlg⁡ND(N)=N\lg ND(N)=NlgN.

We prove this by induction with base case N=1N=1N=1 and inductive hypothesis D(N)=Nlg⁡ND(N)=N\lg ND(N)=NlgN. The goal is to show that D(2N)=(2N)lg⁡(2N)D(2N)=(2N)\lg(2N)D(2N)=(2N)lg(2N).

D(2N)=2D(N)+2N=2Nlg⁡N+2N=2N(lg⁡(2N)−1)+2N=2Nlg⁡(2N) \begin{aligned} D(2N)&=2D(N)+2N \\ &= 2N\lg N+2N \\ &= 2N(\lg(2N) - 1)+2N \\ &= 2N\lg (2N) \end{aligned} D(2N)​=2D(N)+2N=2NlgN+2N=2N(lg(2N)−1)+2N=2Nlg(2N)​

Mergesort uses extra space proportional to NNN, which means it is NOT in-place.

Definition. A sorting algorithm is in-place if it uses ≤clog⁡N\leq c\log N≤clogN extra memory.

Examples. Insertion sort, selection sort, shellsort.

Practical Improvements

  • Use insertion sort for small subarrays.

    Mergesort has too much overhead for tiny subarrays. Cutoff to insertion sort for ≈7\approx 7≈7 items.

  • STOP if already sorted. (especially helpful for partially-ordered arrays.)

  • Eliminate the copy to the auxiliary array.

    Save time (not space) by switching the role of input and auxiliary array in each recursive call.

Complexity of Sorting

Computational complexity is a framework to study efficiency of algorithms for solving a particular problem XXX. It consists of five components:

  • Model of computation. Allowable operations.
  • Cost model. Operation count(s).
  • Upper bound. Cost guarantee provided by some algorithms for XXX.
  • Lower bound. Proven limit on cost guarantee by all algorithms for XXX.
  • Optimal algorithm. Algorithm with best possible cost guarantee for XXX.

We model the complexity of sorting problem as follows:

  • Model of computation. Decision trees.
  • Cost model. # compares.
  • Upper bound. ∼Nlg⁡N\sim N\lg N∼NlgN from mergesort.

Decision Tree

Decision trees for compare-base sorting algorithms can access information only through compare.

Note that the height of the tree hhh === the worst-case number of compares, and at least each leaf corresponds to a possible ordering of elements.

Lower Bound for Sorting

Proposition. Any compare-base sorting algorithm must use at least ∼Nlg⁡N\sim N\lg N∼NlgN compares in the worst case.

We prove this by establishing an inequality based on the number of leaves of decision tree.

  • Binary tree of height hhh has at most 2h2^h2h leaves. # leaves ≤2h\leq 2^h≤2h.
  • N!N!N! different orderings →\to→ at least N!N!N! leaves. # leaves ≥N!\geq N!≥N!.
  • Worst case dictated by height hhh of decision tree.

2h≥2^h\geq2h≥ # leaves ≥N!⇒h≥lg⁡(N!)\geq N!\Rightarrow h\geq \lg(N!)≥N!⇒h≥lg(N!). According to the Stirling's formula, lg⁡(N!)∼Nlg⁡N\lg(N!)\sim N\lg Nlg(N!)∼NlgN.

The lower bound of sorting problem is thus determined by h≥∼Nlg⁡Nh\geq \sim N\lg Nh≥∼NlgN.

We could see that the upper bound and the lower bound overlap each other (∼Nlg⁡N)(\sim N\lg N)(∼NlgN). Therefore, we could say that mergesort is an optimal algorithm for compare-base sorting problem.

Note that quicksort (stay tuned) is NOT optimal: it needs ∼12N2\sim\frac{1}{2}N^2∼21​N2 compares in the worst case.
