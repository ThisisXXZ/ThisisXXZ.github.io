Recursion Problem

关于 Recursion Problem 有大概两种题型：

  • 根据 recurrence equation 求 closed-form。
  • 同时给出 recurrence equation 与 closed-form，证明它们是对应的。

第一种：比较容易的高中数列题。一般来说有两种做法：

  • 根据 recurrence equation，不断将 f(n)f(n)f(n) 拆成 f(n−1)f(n-1)f(n−1)，寻找一系列表达式之间的规律。
  • 从 base case f(1)f(1)f(1) 开始向 f(n)f(n)f(n) 累加，累加的值可用等差/等比数列求和简化。

Amortized/Average Analysis

以 hash table 为例，讲下如何进行时间复杂度的均摊分析。

若 hash table 的容量为 mmm，储存了 nnn 个元素，我们定义其 load factor α=n/m\alpha=n/mα=n/m。

  • chaining (open hashing): # of trials ≈1+a2\approx 1+\frac{a}{2}≈1+2a​.
  • probing (open addressing): # of trials ≈11−α\approx \frac{1}{1-\alpha}≈1−α1​.

可以发现，对于 open addressing 实现的哈希表，我们需要控制 α<12\alpha<\frac{1}{2}α<21​ 来保证常数级别的单次操作复杂度。这就牵扯到了均摊时间复杂度分析的问题：

  • 当 # of elements ≤m2\leq \frac{m}{2}≤2m​ 时，单次插入/查找的平均时间复杂度为 O(1)O(1)O(1)。
  • 当 # of elements reach m2\frac{m}{2}2m​，重建一个容量为 2m2m2m 的哈希表，时间复杂度为 O(m)O(m)O(m)。

在所有插入操作中，只有极小部分会 trigger 哈希表的重建：我们考虑将代价较大的哈希表的重建操作均摊到所有插入操作的代价中。设插入一次的时间代价为 ccc，因为哈希表重建而均摊分配的单次时间代价为 ddd。

为了方便讨论，我们规定从 n=m/4n=m/4n=m/4 开始，每次到下一次哈希表重建为止的所有插入操作将承担哈希表重建的代价。以第一次为例：

  • 目前 n=m/4n=m/4n=m/4，再插入 m/4m/4m/4 次就将触发哈希表重建；因此这 m/4m/4m/4 次操作将承担重建的代价。

  • 重建哈希表所需的时间代价为 2mc2m c2mc.

  • 求出被均摊分配的时间代价 d=2mcm/4=8cd=\frac{2mc}{m/4}=8cd=m/42mc​=8c.

因此单次插入的均摊时间代价为 c+d=9cc+d=9cc+d=9c，O(9c)=O(1)O(9c)=O(1)O(9c)=O(1)，仍然是常数级别。

Insight: Building & Egg Problem

nnn 层楼，kkk 个鸡蛋：求鸡蛋破碎的 critical height。典中典，但确实是一个好问题。

站在复杂度分析的角度，我们定义 T(n,k)T(n,k)T(n,k) 为 optimal # of probes in the worst case，即最坏情况下最优的时间；“最优”体现在存在一个最优的尝试位置，使得最坏时间尽量小。

base case:

  • k=1k=1k=1 时，T(n,1)=nT(n,1)=nT(n,1)=n.
  • k>1k> 1k>1 时，T(0,k)=0,T(1,k)=1T(0,k)=0, T(1,k)=1T(0,k)=0,T(1,k)=1.

其中，每个 T(n,k)T(n,k)T(n,k) 所对应的 optimal_a 就是在该情况下鸡蛋尝试的 optimal position。

一般来说，根据不同的情况，我们采取不同的策略：

  • k=1k=1k=1：别无选择，只能采用 linear search。Θ(n)\Theta(n)Θ(n)。
  • k>1k>1k>1：由于有不止一个鸡蛋，可以采取 jump search 的策略；而其中最优的是 square-root search，即我们熟悉的分块策略。Θ(n)\Theta(\sqrt{n})Θ(n​)。

Radix Sort and Counting Sort

题目来自 2019 COMP2119 Final Exam Q4D (已解禁)。

Given an array of nnn elements, where each element is an integer in {1,2,3,...,nk}\{1, 2, 3, ... , n^k\}{1,2,3,...,nk} for some small constant k≤2k\leq 2k≤2. The task is to sort the elements with asymptotic running time strictly better than O(nlog⁡n)O(n \log n)O(nlogn). (You may use extra O(n)O(n)O(n) space.)

  • 条件 111: 优于 O(nlog⁡n)O(n\log{n})O(nlogn)，考虑 counting sort。
  • 条件 222: Keys range from {1,2,3,...,nk}\{1,2,3,...,n^k\}{1,2,3,...,nk} 但仅有 O(n)O(n)O(n) extra space。考虑 counting sort 的进阶 - radix sort。

如何选取 radix？时刻记住，key range mmm ({1,2,3,..,m}\{1,2,3,..,m\}{1,2,3,..,m})，radix kkk 与 # of digits ddd 满足关系：kd=mk^d=mkd=m，radix sort 的时间复杂度为 O(d(k+n))O(d(k+n))O(d(k+n))。

  • Key range mmm 决定了键值数组的大小。
  • Radix kkk 决定了桶数组的大小。
  • # of digits ddd 决定了进行几轮 counting sort。

回到这道题，kkk 已经保证了是一个 small enough constant，并且我们能使用的额外空间只有 O(n)O(n)O(n)；(桶数组大小) 这提示我们选取 nnn 作为 radix。

  • Key range: nkn^knk
  • Radix: nnn
  • # of digits: log⁡nnk=k\log_n{n^k}=klogn​nk=k

复杂度 O(k(n+n))=O(n)O(k(n+n))=O(n)O(k(n+n))=O(n) since kkk is small.

Binary Search Tree

关于 BST 一些容易忘记的小细节。

Successor

BST 中某节点的后继：

  • the minimum of TRT_RTR​.
  • TRT_RTR​ 不存在：locate an ancestor aaa that is a left child. the successor is aaa's parent.

前驱类似：

  • the maximum of TLT_LTL​.
  • TLT_LTL​ 不存在：locate an ancestor aaa that is a right child. the successor is aaa's parent.

Deletion

删除节点 zzz，分三种情况：

  • zzz has no children: delete zzz.
  • zzz has one child: splice out zzz.
  • zzz has two children: replace zzz by its immediate successor yyy, and splice out yyy (yyy is the minimum of TRT_RTR​ for sure, which means it has at most one child)

定义 splice out 操作为将某点的 children 连到其 parent 上。splice out 只适用于删除只有一个孩子的节点。

Tree Height Analysis

Complexity of insertion and deletion: O(h)O(h)O(h), and the best h=log⁡nh=\log{n}h=logn.

保证树高为 log⁡n\log{n}logn 的重要条件是插入 keys 的随机性，与保证快速排序效率需要 keys 随机性的原理相同。详情见 Algorithms, Princeton 课程的 quicksort 与 BST 部分。

朴素的删除会影响树的结构。在执行若干次删除操作后树会逐渐左倾。

Self-Balanced Tree: Height Analysis

题目来自 2019 COMP2119 Final Exam Q3C (已解禁)。

我们熟悉的 AVL 树就是 b=1b=1b=1 的高度平衡树。

  • N(h−b)N(h-b)N(h−b), the minimum number of nodes in the right subtree of rrr
N(h)=1+N(h−1)+N(h−b) N(h)=1+N(h-1)+N(h-b) N(h)=1+N(h−1)+N(h−b)

Since N(h−1)>N(h−b)N(h-1)>N(h-b)N(h−1)>N(h−b), we can say that

N(h)>1+N(h−b)+N(h−b)=1+2N(h−b)>2N(h−b) N(h)>1+N(h-b)+N(h-b)=1+2N(h-b)>2N(h-b) N(h)>1+N(h−b)+N(h−b)=1+2N(h−b)>2N(h−b)

Randomized Quicksort Analysis

众所周知，快排在序列 already sorted 或 reverse-sorted 时有最坏时间复杂度 O(n2)O(n^2)O(n2)，随机化使得这种情况出现的概率可以忽略不计。但是随机化快排的时间复杂度又怎么分析呢？

当然是取平均！由于随机化，partition 产生的两个子序列的长度可能是 (0,n−1)(0,n-1)(0,n−1), (1,n−2)(1,n-2)(1,n−2) ... (n−1,0)(n-1,0)(n−1,0) 共 nnn 种情况，且概率相等，均为 1n\frac{1}{n}n1​。那么对长度为 nnn 的序列排序所需的时间 T(n)T(n)T(n) 为：

T(n)=2n∑i=0n−1T(i)+cn T(n)=\frac{2}{n}\sum_{i=0}^{n-1} T(i)+cn T(n)=n2​i=0∑n−1​T(i)+cn

  • base case
    • T(0)=0,T(1)=1T(0)=0,T(1)=1T(0)=0,T(1)=1

Huffman Tree: Key lemma

Key lemma of Huffman tree.

Given a tree TTT, we can find a tree T′T'T′, with the two minimum cost leaves as siblings, and C(T′)≤C(T)C(T')\leq C(T)C(T′)≤C(T).

C(T)C(T)C(T) 是 TTT 的 total weighted path length (WPL)。给出一颗树 TTT，不断对其应用 key lemma，其总 WPL 会持续减小。最小 WPL 对应的是 optimal prefix tree， 即 Huffman tree。
